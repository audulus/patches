MIDI Keyboard

Play an Audulus instrument from a MIDI keyboard, sequencer, or other note source. MIDI Keyboard converts notes into pitch and binary gate signals, with selectable polyphony, allocation, sustain, and shared pitch bend.

Setup

  1. Route the intended MIDI source into Audulus or its host.
  2. Select Ch: Omni accepts notes and sustain on all 16 channels; 1–16 accepts one channel.
  3. Select Voices to match your instrument. Connect corresponding pitch and gate voices to its oscillators and envelopes.
  4. Set Pitchbend and its CH selection to match the controller you want to use.

Controls

Control Function
Ch Note and sustain channel: Omni or 1–16. Changing it clears notes and sustain
Voices Mono, Legato, any fixed count from 2 through 16, or Auto
Alloc Default, Rotate, Reset, Newest, or No Steal; described below
Pitchbend Shared bend range, ±1 through ±12 semitones
Pitchbend CH Channel supplying the shared pitch bend; independent of the note channel
Panic Clear notes, sustain, and held pitch bend if a note or pedal becomes stuck

Pitch bend affects every assigned voice together. Selecting a new bend channel centers the held bend. There is no pitch-bend smoothing in the script. MIDI Keyboard is intended for ordinary channel-based playing; use MIDI MPE Keyboard for independent expression on each note.

Voices

Mode Behavior
Mono One voice with last-note priority. New notes retrigger the gate, including overlapping notes. Releasing the newest note returns to an earlier held or sustained note and retriggers when the note changes
Legato One voice with last-note priority. Overlapping notes change pitch while keeping the gate high. Releasing the newest note returns to an earlier held or sustained note without breaking the gate
2–16 A fixed number of polyphonic voices. Choose the count your instrument can process
Auto Up to 16 voice slots. The output count follows the highest sounding slot plus one, with a minimum of one

Auto keeps notes in their assigned slots; it does not pack them into lower slots as other notes end. Its reported count is therefore not necessarily the number of held keys. Changing Voices clears the current notes.

Alloc

Alloc changes how notes are shared between voices in polyphonic modes and Auto. The musical difference is easiest to hear when voices have different sounds or when a note’s release continues after you lift the key.

Mode Musical use When every voice is busy
Default Same as the Audulus keyboard node. Repeating a released note returns to its previous voice when possible, keeping that note’s voice character consistent The earliest-played sounding note gives way to the new note
Rotate Spread successive notes across voices. Repeated staccato notes can use different voices, giving release tails more time to fade and revealing differences between voices The earliest-played sounding note gives way to the new note
Reset Prefer voice 1, then voice 2, and so on as needed. Separate notes usually return to voice 1, useful for a consistent lead sound or a predictable order of voice colors The earliest-played sounding note gives way to the new note
Newest Favor notes you have held longest. Useful for keeping an early bass note or chord tone while replacing more recently added notes The most recently played sounding note gives way to the new note
No Steal Keep the current chord intact. Useful when interrupting a held note would be more distracting than missing an extra note The new note is ignored until a voice becomes available

For example, with four voices, hold C, E, G, then B, and add D. Default, Rotate, and Reset replace C; Newest replaces B; No Steal ignores D. This assumes these are distinct notes and all four voices remain held.

Rotate makes its difference before voices run out: it prefers the voice that has been released longest. Reset takes the first available voice instead. Default, Newest, and No Steal first try to reuse a previous voice for the same note on the same MIDI channel; otherwise they prefer an available voice whose last note started longest ago.

A voice becomes available when its gate falls to zero. The allocator does not know whether the connected envelope has finished its release, so reusing that voice can interrupt or change the tail. Rotate can help spread those tails across voices, but cannot guarantee they finish.

These modes apply to polyphony and Auto. Mono and Legato always use last-note priority. Repeating a note that is still sounding keeps its voice and retriggers its gate; it does not use another voice just because Rotate is selected. Oldest and newest mean playing order, not lowest and highest pitch.

Outputs

Signal Meaning
Pitch (p0–p15) One unit per octave; 0 is A4 / 440 Hz with the default tuning. Shared pitch bend is already added
Gate (g0–g15) 0 or 1. Connect to an envelope gate input. Gate height does not carry velocity
Voice count (ch) Selected fixed count, one in Mono/Legato, or the highest sounding Auto slot plus one

Use matching voice indices: pitch 0 and gate 0 describe the same voice. Pitch holds after release, while unused or released gates are zero. This keyboard does not output velocity, pressure, or timbre.

Sustain and channel controls

CC64 sustain is tracked separately for each accepted MIDI channel. Releasing a key while its pedal is down keeps the note sounding until pedal release. CC120 (All Sound Off) immediately lowers that channel’s gates; CC123 (All Notes Off) releases its keys while respecting sustain. CC121 (Reset All Controllers) clears its sustain and centers bend when received on the selected bend channel. These controls cannot silence a release tail generated independently by the connected instrument.

Script settings

In midi_keyboard.lyte, the user settings are at the top of init:

let voct_center_freq = 440.0
midi_group = 0
pb_channel = 1

voct_center_freq sets the frequency corresponding to pitch 0. midi_group selects the UMP group, numbered 0–15 in the script; group 0 appears as Gr 1 in MIDI Monitor. pb_channel is the fallback bend channel: 1–16 selects one channel, and 0 accepts bend from any channel. A positive pb_ch input overrides this setting; a zero input uses it. The midi_ch input uses integer 0 for Omni and 1–16 for a channel.

Notes

Lyte receives MIDI through receive_ump(), a single queue carrying Universal MIDI Packets (UMP). The script reads MIDI 1.0 channel messages from one-word packets and MIDI 2.0 channel messages from two-word packets, and processes events at their supplied sample offsets. UMP is the packet container; using it does not mean your hardware must support MIDI 2.0.

Audulus may deliver MIDI 1.0 hardware input encoded as MIDI 2.0 packets. Both paths support notes, channel pitch bend, sustain, and the channel controls described above. MIDI 1.0 zero-velocity Note On releases a note; MIDI 2.0 zero-velocity Note On remains Note On. MIDI 2.0 bend uses its 32-bit value before conversion into octave pitch.

MIDI 2.0 per-note controllers, per-note pitch bend, and note attributes are not decoded by this keyboard. MIDI-CI negotiation and device selection are not performed by the script. Select the source through Audulus, your host, or external MIDI routing.
