MIDI Message Input

Receive eight independently assigned MIDI messages as modulation signals for an Audulus instrument. Each output can follow a CC, pitch bend, channel pressure, polyphonic pressure, or note velocity. Use them for filter cutoff, level, timbre, envelope depth, or drum-pad control.

Control outputs hold their latest matching value; note-velocity outputs return to zero on release. All outputs are normalized to 0–1. The first entry in each setup table controls the top output (val0); the eighth controls the bottom output (val7).

Configure the tables

  1. Route your MIDI source into Audulus or its host.
  2. Open the module, select its Lyte DSP node, and open the script editor.
  3. Find the three tables near the top of init in midi_msg_8.lyte. Edit matching entries to choose the message, channel, and number for each output.
  4. Apply the script and save the patch. Send the assigned message and check the corresponding row in the display.

Each column describes the same output in all three tables:

//               val0 val1 val2 val3 val4 val5      val6           val7
message_types = [CC,  CC,  CC,  CC,  BEND, PRESSURE, POLY_PRESSURE, POLY_PRESSURE]
channels      = [1,   1,   1,   1,   1,    1,        1,             1]
numbers       = [1,   74,  11,  7,   0,    0,        60,            64]
Type Input Number entry
CC Absolute Control Change CC number, 0–127
BEND Channel pitch bend Ignored; use 0
PRESSURE Channel pressure / aftertouch Ignored; use 0
POLY_PRESSURE Polyphonic key pressure Note number, 0–127
NOTE_VEL Note On / drum-pad strike velocity Note number, 0–127

Channels are 1–16, independently for each output. Keep eight entries in each table. Multiple outputs can match the same message. The default CC examples are modulation wheel (1), brightness (74), expression (11), and volume (7); actual hardware assignments may differ. The last two outputs listen for polyphonic pressure on note 60 (C4) and note 64 (E4), rather than note velocity. Use NOTE_VEL for drum-pad strikes. Note names can differ between devices; use the MIDI note number for reference.

For example, to put CC74 on channel 2 at output val0, change the first entries to CC, 2, and 74. To receive channel pressure there instead, change those entries to PRESSURE, 2, and 0. Save/apply the edited script; initialization clears held values.

Drum pads

Use NOTE_VEL to receive a pad’s strike velocity. For example, set an output’s three entries to NOTE_VEL, 10, and 36 for note 36 on channel 10. Assign other outputs to other pad notes or channels. MIDI Monitor can identify the note and channel actually sent by your pads; channel 10 is only an example.

The output shows strike velocity as 0–1 while the note is on and drops to zero at the matching Note Off, regardless of release velocity. MIDI 1.0 zero-velocity Note On also clears it; MIDI 2.0 zero-velocity Note On is a valid strike and updates it to zero. MIDI 2.0 strike velocity uses the upper 16-bit velocity field; note attributes do not affect it. Canvas labels show Vel and the assigned note number.

The signal follows the note duration at the strike velocity; it does not generate a fixed-length trigger. Repeated Note On events at the same velocity need an intervening Note Off to create a new rising edge. It can drive a velocity-sensitive gate destination; for envelopes with binary gates, use a separate trigger/gate path and use this output for velocity modulation.

Values and display

Connect val0–val7 to synth parameters. All outputs are 0–1, regardless of display mode. Pitch bend starts at 0.5, with minimum 0 and maximum 1; all other outputs start at 0. Values hold until a matching message arrives. Scale or offset the signal in the instrument when a destination needs a bipolar range or a different depth. There is no automatic smoothing.

display_normalized = true shows 0–1 with three decimal places. Set it to false to show familiar MIDI 1.0 units: 0–127 for CC/pressure/velocity and 0–16383 for bend, centered at 8192. This changes the Canvas text only; it does not reduce output resolution. The arcs always represent 0–1. Canvas snapshots are limited to 30 Hz and carry values to one part per million; output signals are not limited by that display transport.

The Msg and Ch columns show each output’s assignment and channel, aligned with its port. CC 74 means controller 74; Poly 60 means pressure on note 60; Vel 36 means strike velocity on note 36. The number above each port is the current value, and the arc shows its normalized position.

The paired Canvas script is midi_msg_8.lua. When assembling the module yourself, connect any one Lyte output to its Canvas messages input so the script processes and supplies display updates. The supplied module already contains the display connection.

Notes

receive_ump() carries MIDI 1.0 and MIDI 2.0 messages through one queue. Outputs update at the event’s sample offset within each audio block. MIDI 1.0 CC and pressure use 7-bit data and bend uses 14-bit data; supported MIDI 2.0 controls use their 32-bit values and Note On uses its 16-bit velocity before conversion to the floating-point output. Floating-point precision and display rounding still apply.

midi_group = 0 selects UMP group 0, shown as Gr 1 in MIDI Monitor. Use 0–15 to select another group. Audulus may supply MIDI 1.0 hardware events encoded as MIDI 2.0 packets; both encodings are supported.

This receiver handles absolute controls. It does not accumulate relative encoders, assemble MIDI 1.0 high-resolution CC pairs or RPN/NRPN, or decode native MIDI 2.0 per-note controllers. Poly pressure means pressure addressed to a particular note; it is distinct from MPE channel pressure. Note Off clears matching NOTE_VEL outputs. Programs, clock, transport, and SysEx are ignored. Unsupported type/channel/number assignments receive no updates. Use MIDI Monitor to identify the channel, controller number, and message type sent by a device.
